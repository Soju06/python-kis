## 결정에 쓴 것

`needs-decision` 이슈의 완료 기준이 **"근거를 본문에 기록"** 이었습니다.
그래서 먼저 셌습니다.

```text
14일 트래픽    조회 31 / 고유 방문자 2
저장소         stars=0 forks=0 watchers=0
외부 이슈 작성자 0명
```

이슈는 *"영문 문서를 읽는 사람이 있는가 — 측정 수단이 없습니다"* 라고 적었고
`#30` 과 같은 문제라고 했습니다. **그런데 `#30` 과 다릅니다.** `#30` 은
"충분한가"의 기준이 없었고, 여기서는 **간접 신호가 전부 0** 입니다. 0 은
판정 가능합니다.

## 제가 만든 결함 — 검사가 죽은 채로 통과했습니다

`#87` 요건이 영문에 남아 있는지 보는 검사를 이렇게 썼습니다.

```python
assert "live app" in page.lower()
```

되돌리기 확인에서 **요건 문장을 통째로 지웠는데 5건 전부 통과**했습니다.
뒤쪽 설명 문장에도 *"uses the live app key"* 가 있었기 때문입니다.

> **오늘 세션에서 여섯 번 나온 형태를 제가 그대로 만들었습니다.**
> 되돌려 확인하지 않았으면 "검사 5건 추가"라고 적고 끝났을 것입니다.

요건 문장이 든 **문단**을 찾아 `required` · `paper` · `create_client` 가 모두
있는지 보게 고쳤습니다. 문장을 통째로 박지 않은 이유는 표현이 바뀌면 깨지기
때문이고, 문단 단위면 표현이 바뀌어도 "요건으로 읽히는가"는 남습니다.

## 단계는 **범위**만 정합니다 — 조건은 두지 않았습니다

처음에는 단계마다 여는 조건을 붙였습니다(영어 이슈 1건, 첫 스타 …).
**사용자가 조건을 빼라고 정했고, 그 판단이 맞습니다.**

조건을 붙이면 둘 중 하나가 됩니다.

- 조건이 느슨하면 → 신호가 아닌 것에 반응해 번역을 늘립니다
- 조건이 빡빡하면 → `#30` 의 *"충분히 노출되었는가"* 처럼 **아무도 판정하지
  않는 문장**이 하나 더 늘어납니다

그리고 이 저장소에는 조건을 감시할 사람이 한 명뿐입니다. **자동으로 열리는
문이 아니라 그때 여는 문**이면 조건이 필요 없습니다.

그래서 단계는 **각 수준에서 무엇을 유지하는가**만 정합니다. 그것만으로도
값을 합니다 — 늘리기로 한 날 범위를 처음부터 다시 짜지 않아도 됩니다.

| 단계 | 유지 범위 |
|---|---|
| 0 · 현재 | `en/README` 1장 |
| 1 | + `QUICKSTART` |
| 2 | + `FAQ` (오류 메시지 중심) |
| 3 | + 영문 `CONTRIBUTING` |

자세한 것은 [영문 문서 단계 계획](../reports/2026-08-30_EN_DOCS_STAGES.md).
