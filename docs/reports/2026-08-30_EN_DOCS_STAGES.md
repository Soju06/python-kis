## 왜 조건을 두지 않는가

초안에는 단계마다 여는 조건이 있었습니다(*영어 이슈 1건*, *첫 스타*,
*외부 PR 1건*). **뺐습니다.**

조건을 붙이면 둘 중 하나가 됩니다.

- **느슨하면** — 신호가 아닌 것에 반응해 번역을 늘립니다. 스타 하나가 영문
  QUICKSTART 를 유지할 이유가 되지 않습니다
- **빡빡하면** — [`#30`](https://github.com/visualmoney/vm-stock-kis/issues/30)
  의 *"0.0.x 가 실사용자에게 충분히 노출되었는가"* 처럼 **아무도 판정하지 않는
  문장**이 하나 더 늘어납니다. 그 문장이 서브이슈 4건을 8개월 묶었습니다

그리고 이 저장소에는 조건을 감시할 사람이 한 명뿐입니다. **감시자가 곧 판단자면
조건은 판단을 대신해 주지 못합니다.**

> 단계표가 정하는 것은 **"언제"** 가 아니라 **"무엇을"** 입니다. 늘리기로 한
> 날 범위를 처음부터 다시 짜지 않아도 된다 — 그것이 이 표의 전부이고,
> 그것으로 충분합니다.

## 0단계

### 유지하는 것

`docs/user/en/README.md` **한 장**. 담는 것은 넷입니다.

1. 이 라이브러리가 무엇인가 (한국투자증권 Open Trading API · **주식 현물만**)
2. 설치 한 줄
3. **실전 앱 등록 요건** — 모의만 거래해도 필요합니다
   ([`#87`](https://github.com/visualmoney/vm-stock-kis/issues/87))
4. "전체 문서는 한국어" + 한국어 문서로 가는 표

### 3번이 왜 이 한 장에 들어가는가

영문이 세 장이던 시절, 이 요건은 **영문 어디에도 없었습니다.** 영문
`QUICKSTART` 를 따라간 사용자는 모의 앱만 적힌 설정을 만들고 `create_client()`
에서 막혔습니다.

한 장으로 줄였으므로 **그 한 장이 이 요건을 집니다.** 검사가 감시합니다
(`tests/unit/test_english_docs_scope.py`).

### 하지 않는 것

- 한국어 문서의 요약본을 영문으로 만들지 않습니다. **요약본도 드리프트합니다**
- 코드 예제를 영문 페이지에 늘리지 않습니다. 실행 가능한 코드는 번역이
  필요 없으므로 [`examples/`](../../examples/) 로 보냅니다

### 유지 비용

릴리스마다 **설치 줄과 코드 한 조각**만 확인하면 됩니다.

## 1단계 — 영문 `QUICKSTART`

### 유지하는 것

0단계 + 설치부터 첫 조회까지 한 장.

### 범위

**현재 한국어 `QUICKSTART.md` 에 대응하는 것 하나**입니다. 한국어 원본은
지금 89줄이고 제목이 하나입니다 (2026-08-30 실측).

옛 영문 `QUICKSTART` 는 **333줄에 8개 절**이었습니다 — 최신 한국어의 번역이
아니라 **사라진 판본의 번역**이었습니다. 1단계로 갈 때 그 문서를
`archive/docs/user/en/2026-08_QUICKSTART.md` 에서 **가져오지 마세요.** 현재
한국어를 보고 새로 써야 합니다.

### 하지 않는 것

- 설정 스키마를 영문에 **다시 적지 않습니다.**
  `docs/guidelines/CONFIG_SCHEMA.md` 가 정본이고, 스키마가 바뀌면 번역본이
  먼저 틀립니다. 링크로 보냅니다
- Troubleshooting 절을 만들지 않습니다. 그것은 2단계입니다

### 유지 비용

한국어 `QUICKSTART` 가 바뀔 때마다 한 장. **이 문서가 드리프트하면 사용자가
막히는 자리**이므로 비용이 가장 비쌉니다.

## 2단계 — 영문 `FAQ`

### 유지하는 것

1단계 + FAQ 한 장.

### 범위

**한국어 `docs/FAQ.md` 의 번역이 아닙니다.** 실제로 물어본 것과 **오류 메시지**
만 담습니다.

옛 영문 `FAQ` 는 574줄이었고 한국어(601줄)를 통째로 옮기려다 실패했습니다.
`#70` 이 없앤 `virtual`/`sandbox` 를 마지막까지 가르치고 있었습니다.

### 왜 오류 메시지 중심인가

오류 메시지는 **코드에 있습니다.** 메시지가 바뀌면 문서가 틀린 것이 드러나고,
검사로 대조할 수도 있습니다. 개념 설명은 그렇지 않습니다 — 조용히 낡습니다.

### 하지 않는 것

- 한국어 FAQ 의 항목을 미리 옮겨 두지 않습니다. **물어본 것만** 넣습니다

## 3단계 — 영문 `CONTRIBUTING`

### 유지하는 것

2단계 + 기여 절차 한 장.

### 범위

브랜치·커밋 관례, 테스트 실행 방법, PR 형식. **`CONTRIBUTING.md` 전체가
아니라 외부 기여자가 첫 PR 을 내는 데 필요한 만큼**입니다.

### 하지 않는 것

- 아키텍처 문서를 영문으로 만들지 않습니다. 기여자가 거기까지 가면 코드를
  읽습니다

## 어느 단계에서든 지키는 것

이 세 가지는 **영문이 세 장이던 시절에 실제로 깨진 것**입니다.

| | 규칙 | 깨졌을 때 무슨 일이 났나 |
|---|---|---|
| 1 | **숫자를 손으로 적지 않는다** | 옛 `en/README` 가 `coverage-92%` 배지를 박아 두었습니다 |
| 2 | **없는 파일을 링크하지 않는다** | 옛 `en/README` 가 `./CONFIGURATION.md` 와 `../ko/README.md` 를 가리켰습니다. 후자는 **존재한 적이 없습니다** |
| 3 | **한국어에 있는 요건을 빠뜨리지 않는다** | `#87` 이 영문에 오지 않아 사용자가 막혔습니다 |

1·2·3 전부 `tests/unit/test_english_docs_scope.py` 가 봅니다. **단계를 올릴
때 그 검사도 함께 올려야 합니다** — 지금은 `README` 한 장만 봅니다.

### 검사가 막는 것

**영문을 늘리는 것이 아니라 아무도 모르게 늘어나는 것**입니다.
`docs/user/en/` 에 파일을 추가하면 검사가 빨개지고, 그때 이 문서를 다시 읽게
됩니다. 단계를 옮기기로 정했으면 `KEPT` 에 넣고 근거를 남기면 됩니다.

## 단계를 내리는 경우

올리는 것만 단계가 아닙니다. **유지되지 않는 장이 생기면 내립니다.**

판단 기준은 하나입니다 — *"지금 이 문서를 따라 하면 되는가?"* 아니면 내리는
것이 맞습니다. **틀린 안내는 없는 안내보다 나쁩니다.** 읽는 사람은 그것이
낡았다는 것을 알 방법이 없습니다.

내릴 때는 지우지 않고 `archive/docs/user/en/` 으로 보냅니다
([`archive/README.md`](../../archive/README.md)).
